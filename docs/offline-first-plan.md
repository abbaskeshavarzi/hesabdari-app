# برنامه فاز اول برای آنلاین/آفلاین کردن اپ

هدف فاز اول این است که قبل از تغییرات پرریسک روی ثبت فاکتور و انبار، زیرساخت و معیارهای پذیرش offline-first مشخص شود.

## حالت‌های کاری پیشنهادی

- **آنلاین:** عملیات مستقیماً در Supabase ثبت می‌شود و خطای شبکه به کاربر نمایش داده می‌شود.
- **آفلاین:** عملیات در IndexedDB و صف همگام‌سازی ذخیره می‌شود؛ کاربر بعداً دستی sync می‌کند.
- **خودکار:** اگر اینترنت برقرار باشد عملیات sync می‌شود؛ در غیر این صورت در صف می‌ماند و با برگشت اتصال ارسال می‌شود.

## اجزای فنی لازم در فازهای بعدی

1. IndexedDB برای snapshot داده‌ها و صف عملیات.
2. شناسه local برای رکوردهای آفلاین تا قبل از گرفتن شناسه قطعی Supabase.
3. `sync_queue` با نوع عملیات، payload، زمان ایجاد، تعداد تلاش و وضعیت خطا.
4. UI وضعیت همگام‌سازی در Layout: آنلاین، آفلاین، در انتظار ارسال، خطای sync.
5. سیاست conflict برای فاکتور و موجودی کالا؛ موجودی باید هنگام sync روی سرور دوباره اعتبارسنجی شود.
6. تست integration برای سناریوهای قطع/وصل اینترنت.

## ترتیب پیشنهادی اجرا

1. پیاده‌سازی queue برای داده‌های کم‌ریسک‌تر مثل مشتری، کالا و پرداخت.
2. اضافه کردن sync دستی و گزارش خطا.
3. اضافه کردن فاکتور آفلاین با شماره موقت.
4. حل conflict موجودی و شماره فاکتور در RPC سمت دیتابیس.
5. تست روی Android Chrome، iOS Safari و Windows Edge/Chrome.
