# دفتر حساب — وب اپ حسابداری شخصی

اپ ساده حسابداری با Next.js + Supabase. مشتریان، فاکتورها، وضعیت حساب و گزارش فروش دوره‌ای را مدیریت می‌کند.
کاملاً رایگان: هاست روی GitHub Pages، دیتابیس و لاگین روی Supabase (پلن رایگان).

## مرحله ۱ — ساخت پروژه Supabase (دیتابیس + لاگین)

1. به [supabase.com](https://supabase.com) بروید و رایگان ثبت‌نام کنید.
2. یک پروژه جدید بسازید (نام دلخواه، رمز دیتابیس را جایی یادداشت کنید).
3. از منوی سمت چپ وارد **SQL Editor** شوید، فایل `supabase-schema.sql` این پروژه را باز کنید، محتوایش را کپی و در ادیتور Paste کنید، سپس **Run** بزنید. این کار جدول‌های مشتری، فاکتور و پرداخت را می‌سازد.
4. وارد **Authentication > Users** شوید و با دکمه **Add user** یک کاربر بسازید (ایمیل و رمز عبور خودتان — همین برای ورود به اپ استفاده می‌شود).
5. وارد **Project Settings > API** شوید و دو مقدار زیر را کپی کنید:
   - **Project URL**
   - **anon public key**

## مرحله ۲ — تنظیم پروژه روی سیستم خودتان (اختیاری، برای تست قبل از انتشار)

1. [Node.js](https://nodejs.org) نسخه ۲۰ به بالا را نصب کنید.
2. فایل `.env.local.example` را کپی کرده و به `.env.local` تغییر نام دهید، مقادیر Supabase مرحله قبل را در آن قرار دهید. بدون این دو مقدار، build فقط با مقدارهای placeholder ساخته می‌شود و اتصال واقعی به دیتابیس کار نمی‌کند.
3. در پوشه پروژه دستورات زیر را اجرا کنید:
   ```
   npm install
   npm run dev
   ```
4. آدرس `http://localhost:3000` را در مرورگر باز کنید و با ایمیل/رمزی که در Supabase ساختید وارد شوید.

## مرحله ۳ — انتشار رایگان روی GitHub Pages

1. یک ریپازیتوری جدید در GitHub بسازید (مثلاً `hesabdari-app`) — عمومی یا خصوصی، فرقی ندارد.
2. کدهای این پروژه را در آن push کنید:
   ```
   git init
   git add .
   git commit -m "نسخه اول"
   git branch -M main
   git remote add origin https://github.com/USERNAME/hesabdari-app.git
   git push -u origin main
   ```
3. در ریپازیتوری، وارد **Settings > Secrets and variables > Actions** شوید و دو Secret زیر را اضافه کنید:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   (همان مقادیری که از Supabase گرفتید)
4. وارد **Settings > Pages** شوید، در بخش **Build and deployment > Source** گزینه **GitHub Actions** را انتخاب کنید.
5. یک بار دیگر تغییری push کنید (یا از تب Actions، workflow را دستی اجرا کنید). بعد از چند دقیقه آدرس اپ شما در همان صفحه Pages نمایش داده می‌شود، چیزی شبیه:
   `https://USERNAME.github.io/hesabdari-app/`

از این به بعد، هر بار که کدی روی برنچ `main` push کنید، اپ به‌صورت خودکار به‌روزرسانی می‌شود — بدون هیچ هزینه‌ای.

## بخش‌های اپ

- **مشتریان**: نام، تماس، آدرس، وضعیت حساب (بدهکار/بستانکار/تسویه) و مبلغ آن — با جست‌وجو.
- **کالاها**: لیست کالا/خدمت با قیمت واحد و موجودی فعلی.
- **انبار**: ثبت ورود/خروج کالا و تاریخچه تراکنش‌های انبار.
- **فاکتورها**: ثبت فاکتور برای هر مشتری با چند قلم کالا، شماره فاکتور خودکار، وضعیت پرداخت — با جست‌وجو، چاپ، ذخیره به‌صورت عکس، و آماده‌سازی پیامک برای مشتری.
- **پرداخت‌ها**: ثبت پرداخت هر مشتری؛ به‌صورت خودکار از بدهی او کم می‌شود.
- **گزارش فروش**: مجموع فروش در یک بازه تاریخی دلخواه.
- **داشبورد**: خلاصه تعداد مشتریان، مطالبات باز و فروش ماه جاری.

### به‌روزرسانی دیتابیس برای «کالاها» و «انبار»

اگر پروژه رو از قبل راه‌اندازی کرده بودی، فقط کافیه فایل `supabase-migration-2-inventory.sql` رو در Supabase SQL Editor اجرا کنی (نیازی به اجرای دوباره `supabase-schema.sql` نیست).

### به‌روزرسانی دیتابیس برای «فاکتور با چند قلم کالا»

فایل `supabase-migration-3-invoice-items.sql` رو هم در Supabase SQL Editor اجرا کن. از این به بعد هر فاکتور می‌تونه چند قلم کالا داشته باشه و با ثبت فاکتور، موجودی انبار خودکار کم می‌شه.

### به‌روزرسانی دیتابیس برای «وضعیت پرداخت فاکتور»

فایل `supabase-migration-4-invoice-status.sql` رو در Supabase SQL Editor اجرا کن. از این به بعد هر فاکتور یک وضعیت (معوق / نیمه‌پرداخت / پرداخت‌شده) داره که مستقیم از لیست فاکتورها قابل تغییره.

### به‌روزرسانی دیتابیس برای «فاکتور با چند قلم کالا»

همچنین فایل `supabase-migration-3-invoice-items.sql` رو هم در SQL Editor اجرا کن. از این به بعد، هر فاکتور از یک یا چند قلم کالا تشکیل می‌شه و با ثبت فاکتور، موجودی کالاهای مربوطه به‌صورت خودکار کم می‌شه.

⚠️ نکته: در حال حاضر حذف یک فاکتور، موجودی کالا را به‌صورت خودکار برنمی‌گرداند.

### تنظیم اطلاعات فاکتور چاپی

دیگه نیازی به ویرایش کد نیست! از داخل خود اپ برو به صفحه **تنظیمات** و نام، تلفن، آدرس و لوگوی کسب‌وکارت رو وارد کن. این اطلاعات هم توی نوار کناری و هم روی فاکتور چاپی نمایش داده می‌شه.

### به‌روزرسانی دیتابیس برای «تنظیمات کسب‌وکار»

فایل `supabase-migration-5-business-settings.sql` رو در Supabase SQL Editor اجرا کن. این کار یک جدول برای اطلاعات کسب‌وکار و یک فضای ذخیره‌سازی برای لوگو می‌سازه.

## امنیت

- ورود فقط از طریق حساب Supabase که خودتان ساختید امکان‌پذیر است.
- سطح دسترسی دیتابیس (Row Level Security) فعال است. برای پروژه‌های جدید، پس از اجرای migrationهای قبلی، فایل `supabase-migration-12-security-hardening.sql` را هم اجرا کنید تا داده‌ها بر اساس `auth.uid()` از هم جدا شوند.
- اگر دیتابیس را قبلاً با یک کاربر راه‌اندازی کرده‌اید، بعد از اجرای migration 12 مقدار `user_id` رکوردهای قدیمی را با UUID کاربر اصلی خود پر کنید؛ نمونه دستور داخل خود migration نوشته شده است.
- کلید `anon key` برای استفاده در فرانت‌اند طراحی شده و به‌تنهایی اجازه دور زدن RLS را نمی‌دهد.
- فایل‌های لوگو در bucket عمومی `logos` خوانده می‌شوند، اما مسیر نوشتن/ویرایش آن‌ها به پوشه کاربر لاگین‌شده محدود شده است.
- سرویس‌ورکر درخواست‌های Supabase و صفحات حساس مثل پشتیبان‌گیری و چاپ فاکتور را cache نمی‌کند؛ هنگام خروج از حساب نیز cache اپ پاک می‌شود.

## نصب اپ روی صفحه اصلی گوشی (PWA)

- **آیفون (Safari):** آدرس اپ رو باز کن → دکمه Share (مربع با فلش رو به بالا) → **Add to Home Screen**.
- **اندروید (Chrome):** آدرس اپ رو باز کن → منوی سه‌نقطه → **Add to Home screen** یا **Install app**.

بعد از نصب، اپ با آیکون اختصاصی روی صفحه اصلی گوشی ظاهر می‌شه و بدون نوار آدرس مرورگر، مثل یک اپ واقعی باز می‌شه.

⚠️ نکته فنی: مسیر آیکون‌ها و مانیفست در فایل‌های `public/manifest.json`، `pages/_document.js` و `pages/_app.js` بر اساس نام ریپازیتوری `hesabdari-app` تنظیم شده. اگر اسم ریپازیتوری رو عوض کردی، باید `/hesabdari-app/` رو توی این سه فایل با نام جدید جایگزین کنی.
